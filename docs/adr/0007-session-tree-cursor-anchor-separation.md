# pi-session-tree 光标节点与 @ 锚点（叶子）的语义分离

pi-session-tree 面板的 g 跳转表达式中，`@`/`@~N`/`@^`/`@^^type` 以「会话当前节点（叶子）」为解析锚点（不随面板光标移动），`+N`/`-N` 以「光标节点」为基准。筛选/搜索视图会过滤可见节点，导致「光标所见节点」与「@~ 所选节点」不一致——这是渲染层的割裂，通过 footer 提示（「筛选视图(光标≠@~所选)」/「搜索视图(光标≠@~所选)」）解决，而非把 @ 改成光标基准（那会让 @~N 随光标漂移、失去「会话锚点」的稳定语义）。

## `@~N` 与 `+N`/`-N` 的步进语义

两者都跳过「无文本且非 error/aborted 的 assistant 消息」（`isNoTextAssistant`）。这只对齐了面板「隐藏无文本 assistant」这一条规则，**不等于**与可见列表完全对齐——面板默认视图还隐藏 SETTINGS_TYPES（`custom`/`model_change` 等），`@~N`/`+N`/`-N` 仍会把它们计入步数。二者遍历的**顺序**也不同：

- `@~N` 沿「叶子到根的路径」回退 N 步（只看当前分支的祖先链）。
- `+N`/`-N` 沿「DFS 全序」偏移 N 步（`offsetNode` → `collectNodes` 过滤后），可跨分支。

此外，面板的可见列表还会叠加**动态**过滤（filterMode、搜索 query、折叠分支的后代、活跃分支优先重排），这些是 `resolve()` 无法感知的 UI 状态。因此 `+N`/`-N` 落在被动态隐藏的节点时，面板通过 `revealNode()` + 切 `all` 过滤兜底揭示（见 `ui/panel.ts` 跳转执行逻辑），而非让 `resolve()` 感知 UI 状态。
