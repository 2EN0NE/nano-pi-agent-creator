# ADR-0032: preset 三级来源配置（会话内存 / 项目文件 / 全局文件）

- 状态：已接受（2026-09）；决策 2（会话级仅存内存）与决策 5（撤销硬编码默认）已被 ADR-0033 取代
- 相关组件：`extensions/meta/preset.ts`

## 背景

preset 配置原先只有两级（用户级 + 项目级 config.json），且曾引入硬编码默认 preset
（`DEFAULT_PRESETS`，plan/implement 两套）。两个问题：

1. **无临时试验能力**：想在会话内临时改 thinkingLevel/instructions，只能去改配置文件，
   污染持久配置，或另建一个长期 preset。
2. **硬编码默认与「配置文件即事实」冲突**：把两套 preset 写死在代码里，用户看不到也改不到，
   且与「用户/项目级只能通过配置文件改」的边界不一致。

参照 permission-gate 的三级持久化（session/project/user），preset 需要同样的**来源分级**，
但有一个关键差异：permission-gate 的会话级是**落盘**的（`<sessionId>.json`），而 preset 的
会话级应是**纯内存、不持久化**（临时试验，会话结束即失效）。

## 决策

1. **preset 三级来源**：`session`（会话内存）> `project`（项目配置文件）> `user`（用户配置文件，
   面板显示为「全局」）。同名 shadow，面板每行头部标 `[会话]/[项目]/[全局]`。
2. **会话级仅存内存**（`Map`），`session_shutdown` 清空，不做文件持久化。
3. **会话级只能 TUI 操作**：`n` 新建（只填名称）、`e` 编辑字段（选择器）、`d` 删除、
   `s` 提升为项目级。**文件级（项目/全局）只能改配置文件**，TUI 中 `e` 键语义为
   「复制为临时」（`原名-复制`，重名递增），不改原文件。
4. **提升（promote）**：会话级 `s` 写入项目级 config.json（读-改-写，保留其他 preset）
   并移除会话级条目，实现「临时试验 → 项目固化」。不提供 TUI 提升到全局级（影响面大，
   用户自行拷贝文件）。
5. **撤销硬编码默认**：无 config.json 时 presets 为空，面板提示 No presets defined。
   开箱即用靠用户级种子 config.json（由用户在 `~/.pi/agent/extensions-data/preset/` 维护）。

## 权衡

| 方案                                      | 结论                                                             |
| ----------------------------------------- | ---------------------------------------------------------------- |
| A. 会话级落盘（复用 pi-state session 层） | 拒绝：临时试验会残留会话文件，语义上「临时」就应不持久化         |
| B. 会话级纯内存（本决策）                 | 采纳：临时性心智模型清晰，session_shutdown 自然清理              |
| C. 文件级也可 TUI 原地编辑                | 拒绝：与「文件级只能配置文件改」边界冲突，且原地改文件有覆盖风险 |
| D. 硬编码默认 preset                      | 拒绝：与「配置文件即事实」冲突，用户看不到也改不到               |

## 后果

- **正向**：会话级提供安全的「试验场」（试错了会话结束自动消失）；提升让试验结果可固化；
  三级来源标记让每个 preset 的来源和可编辑性一目了然。
- **负向**：面板交互变复杂（新增 n/d/e/s 键 + 编辑模式）；会话级 preset 不跨会话（/reload
  或重启后丢失），用户须在会话结束前提升，否则临时配置丢失。
