# pi-lab 定位：从 bandit 在线优化转向测量+分析基础设施

**状态**: accepted

pi-lab 最初的 `select()` 用 Thompson Sampling 做在线选臂（多臂老虎机），自动把流量倾斜给赢家臂。这与用户想要的"AB 测试平台"定位（搜集实验数据、给出分析结论）在数学上互斥——bandit 破坏统计有效性（流量不等分、无固定样本量、无法做显著性检验）。

我们决定：pi-lab 回归纯基础设施——`select()` 默认均匀随机 + 稳定哈希分桶，不做自动选臂；Thompson Sampling 降级为显式 opt-in 的分配策略；分析结论由新增的 `query()` 给出（均值/置信区间/胜出概率）；切换 arm 的决策交还消费方（smart-context 等）。

## 考虑过的选项

- **保留 bandit 为默认**（在线优化、自动倾斜流量）：被否决——与"给出分析结论"的 AB 平台定位互斥，无法做统计显著性检验。
- **回归测量+分析，bandit 为 opt-in**：采纳——测量/存储/分析是纯基础设施，决策是消费方的领域逻辑。
