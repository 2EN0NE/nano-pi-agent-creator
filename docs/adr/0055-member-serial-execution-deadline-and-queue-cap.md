# ADR-0055: 成员串行执行——一次一个任务、完成时限、排队上限

- 状态：**已接受**（2026-09-14）：人类裁定 `D3` 逾期动作 = ②「标记逾期 + 通知派发人与人类（不自动回落）」、`D4` = 「满则拒绝派发」（默认上限每成员 3，可配、实测再调）、`D6` = **保留两级**（默认 L1）。落地票见文末「落地票」。本 ADR **取代**同日草案《任务优先级与抢占语义》——那份草案的**优先级档位与并发概念已按人类决定放弃**（见「背景」）
- 相关组件：`extensions/auto/org`（`types.ts` 任务模型、`task.ts` 状态机、`dispatch.ts` 投递、`index.ts` 工具与命令、`board.ts` 看板）、`extensions/auto/control`（abort 通道）
- 延伸：承接 ADR-0054（投递-触发闭环）；沿用 ADR-0048（授权面：谁能对成员做什么）、ADR-0053（中断语义与据实回报）；实现**抄** `pi-subagents-1`
- 术语：**新增**（定稿后入 `CONTEXT.md`）：执行槽（execution slot）、占用租约（lease）、完成时限（deadline）、排队上限（queue cap）、逾期（overdue）、显式抢占（explicit preemption）

## 背景

### 人类的决定（2026-09-14）

> 「就限定一次完成一个任务，只不过给限定完成的时限，不要进入并发的概念。但可以引入排队上限。」

即：**不引入优先级档位、不引入并发**，改为「**串行 + 时限 + 上限**」三个约束。

### 为什么这个方向是对的（有证据，不是妥协）

1. **成员本来就是一条对话线程**：pi 的投递语义（`steer` / `followUp`，`agent-session.js:1112-1119`）是**轮次串行**——成员侧根本不存在并发，只有"排队等着"。所谓"并发控制"在成员这一层是**伪需求**。
2. **生态无先例**：4 个参考框架（`pi-subagents`、`pi-subagents-1`、`pi-dynamic-workflows`、`pi-background-tasks`）里**没有任何任务优先级队列或抢占**——`priority` 的命中只有三类：OpenAI 的计费档 `fast: true`、内部 checklist 排序启发（`pi-subagents-1/src/workflows/workflow-checklist.ts:294`）、skills 来源优先级。⇒ 优先级是**未被验证的发明**；而"一次一个 + 容量上限 + 满了拒收"恰恰是它们都做的（`active-async-capacity.ts`）。
3. **绕开优先级反转**：优先级反转（Lamport / Sha 等命名的问题）在"不排序"的前提下**自然消失**——没有优先级就无所谓反转。而且用**时限**表达紧急比用**档位**更可执行：时限是可验收的，档位只是标签。

### 现状（同一批事实，带行号）

- `Task` **无 priority**（`types.ts:200-229`）；`dueAt`（`types.ts:206-207`）只做展示与继承，**不参与任何判定**；
- 成员侧**没有"同时只做一件"的显式约束**，也**没有"占用"概念**——`runtime/<member>.json` 只表达"进程在不在岗"，**不表达"某个任务在不在执行"**；
- **没有任何排队上限**：投递要么在线送达，要么落 `inbox/`，而 `inbox/` 可以无限增长；
- 唯一的中断手段是 `org_abort`（ADR-0053）——**保留**，作为显式抢占的基础。

## 决策

### D1 串行执行：成员同一时刻只处理一个任务（并发 = 1）

成员侧不存在并发（一条对话线程）。因此本 ADR **不引入**并发度、优先级队列、按优先级抢占；"多个任务"只表现为**排队**。

- 已确证的边界：成员仍可能被派多个**子任务**——串行意味着它们**顺序**执行，后到者等待；等待时长由 `D3`（时限）与 `D4`（上限）共同约束。

### D2 执行槽与占用租约（抄 `pi-subagents-1` 的容量实现）

每成员一个**执行槽**；"某任务正在执行" = 该槽被占用，占用者带**租约标识**（`reservationToken` + `generation`），抄 `active-async-capacity.ts:60-150`。

- 作用：让"在跑 / 空闲"成为**可判定、可回收**的事实，而不是靠推断；
- **回收必须保守**（同 ADR-0054 `D4` 末条）：只有**证明已死**（PID 存活校验 + 失败证据）才释放槽；时间阈值仅作兜底，可配置 / 可禁用（`active-async-capacity.ts:11-13,87,238-242`）；
- 与既有 `presence` 的关系：presence 表达**进程**在不在岗，执行槽表达**任务**在不在跑——两者都需要，**不可互相替代**（现在只有前者）。

### D3 完成时限（deadline）

任务带**完成时限**（可空），语义为"必须在此时间前完成"。

- **字段（定稿）**：**复用既有 `dueAt`**，语义收紧为「完成时限」；未设置则不判逾期。不新增字段（简洁优先，且无迁移成本）。
- **可观测**：剩余时限进入成员简报（ADR-0054 `D5` 的清单）与看板，与队列一起显示（`D5`）。
- **超时判定者**：巡检（presence / `D2` 的回收循环）判定并留痕（`D7`）；判定必须保守——对**活着且在跑**的任务只标记、不释放。
- **逾期后的动作（定稿，人类裁定 2026-09-14）**：**标记逾期 + 通知派发人与人类**；**不自动回落**（是否改派 / 打回由派发人或人类决定）。

### D4 排队上限（queue cap）

每成员的待办队列上限 N（可配置）：

- **满了就明确拒绝**新派发（报错 + 提示改派或等待），**不静默堆积**——抄 `active-async-capacity.ts:74` 的 `ActiveAsyncCapacityError("capacity exhausted: used/limit")` 语义（明确、可判定、可测）；
- **默认值（定稿）**：每成员 **3**（经 `@zenone/pi-config` 双层可配），**实测后再调**；超限一律**拒绝**，不落 `inbox/` 堆放（定稿，人类裁定 2026-09-14）。
- 与 ADR-0054 的关系：`inbox/` 仍是**权威落点**，但"入队"受上限约束——两者不矛盾：**投递可靠 ≠ 队列无限**。

### D5 排队与时限可见

看板 / `org_fleet` 显示：当前执行中的任务、**队列长度与排队位置**、**剩余时限**（不可见就无法干预——同 ADR-0052 的论证）。

### D6 紧急通路：显式抢占（**不做优先级字段**）

- 唯一"插队"手段 = **显式抢占**：`org_abort`（停当前轮，ADR-0053）+ 立即投递，**合成一条命令**；
- 权限沿用 ADR-0048：人类或该 org 负责人；
- **两级（定稿，人类裁定 2026-09-14）**：L1 `steer`（温和插话，**不中断**当前轮；`agent-session.js:1116`）为**默认**；L2 `org_abort`（硬抢占）需**显式**指定。理由：`steer` 属于**中断/插话语义**，不产生第二个执行线程，与 `D1` 的串行前提不矛盾；而硬抢占会丢失当前轮进度——打断正在写文件 / 长工具链的代价通常高于等几秒。
- **明确不做**：`priority` / `urgent` 字段、按优先级排序、并发档位（生态无先例 + 人类决定）。

### D7 可指认

逾期、拒收（队列满）、抢占（谁、何时、打断时它在做什么）全部入任务 history——这是「验证」的前提。

## 后果

- ✅ 模型简单且**可验收**：一次一件 + 有时限 + 有上限——不需要优先级，也不需要并发调度；
- ✅ 生态可抄：执行槽 / 租约 / 保守回收 / 满则拒收，在 `pi-subagents-1` 已有成熟实现（引入的是被验证过的机制，不是新发明）；
- ⚠️ "紧急"的表达从"打标签"变成"**人显式抢占**"——人类操作成本上升，但被滥用（人人 P0）的风险下降；
- ⚠️ 时限若没有对应动作，等于没有时限——已定：标记逾期 + 通知，由派发人决定去向（`D3`）；
- ⚠️ 队列上限太小会把"派活"变成频繁失败——默认 3，**需实调**（`D4`）。

## 验证

1. **单测 / 组件**：队列满 → 明确拒绝（错误信息含 `used/limit`）；释放后可再入队；
2. **组件**：执行槽被占用 → 新任务进入**排队**（不并发执行）；槽回收**只在证明已死**时发生（活进程不被误回收）；
3. **e2e**：任务带时限 → 逾期后按 `D3` 的动作生效且留痕（history 出现 `overdue` 或等价事件）；
4. **e2e**：显式抢占（abort + 投递）→ 当前轮中断、`interrupted` 入 history、成员随后处理新任务（复用 ADR-0053 的 abort 通道）；
5. **e2e（回归）**：无上限压力下的正常派发-交付闭环不变。
