# ADR-0023: TUI 视觉规范补全——字符白名单、纯横线边框范式与三层验收

- 状态：已接受（2026-08-22）
- 相关组件：`docs/tui-design-principles.md`、`docs/tui-interaction-patterns.md`、`src/tui-testing/`、全体 TUI 扩展

## 背景

`docs/tui-design-principles.md` 早已立下「无 emoji/图标」「theme 颜色」「`truncateToWidth` 兜底」「`visibleWidth` 对齐」等规则，
但存在三处规则与现实脱节：

1. **「无 emoji」自相矛盾**：文档 §1.1 禁一切图标，但文档自己的示例和几乎所有扩展的 footer 都用 `↑↓` 导航提示；
   AGENTS.md 甚至把 `→` 也列为禁止。执行者无法判断「单宽箭头」和「双宽 emoji」的边界。
2. **边框风格三派并存**：方角竖线盒（quit、btw）、圆角竖线盒（custom-compaction、answer）、方角无竖线（pi-lab、pi-shortcuts）。
   竖线边框要求每一行精确计算 `rightPad` 保证右边框对齐，是「右边框错位」类 bug 的最大来源（§7.5 一整章都在解决它）。
3. **有规则无门禁**：40+ 带 UI 的扩展里硬编码颜色（answer、quit、session-breakdown 等）、双宽 emoji（btw、prompt-editor、
   files/ui 等）大量存在，全靠人工 review 纠正，无人执行。

## 决策

### 1. 字符白名单（替换模糊的「无 emoji」）

| 类别              | 字符                                      | 结论                                                                                 |
| ----------------- | ----------------------------------------- | ------------------------------------------------------------------------------------ |
| 单宽箭头          | `↑` `↓` `←` `→`                           | **允许**。宽度恒为 1，无崩溃风险，仅用于键盘导航提示                                 |
| 双宽 emoji / 图标 | `✓` `✗` `⭐` `📋` `☑` `☐` `✎` `⚙` `❌` 等 | **禁止**。宽度不确定（单宽/双宽随终端变化），改用纯文本 `OK`/`BLOCK`/`[x]`/`[ ]`/`>` |
| 状态标记          | —                                         | 一律纯文本：`OK`/`FAIL`/`BLOCK`、`>` 选中、`_` 光标                                  |

**豁免（不受白名单约束）**：

- `catch-the-fox`：像素网格渲染需直接输出 ANSI 转义（非 Pi TUI 渲染路径）。
- `pi-tmux-status`：`🟢🟡🔴` 在 tmux 状态栏（Pi TUI 之外），宽度由 tmux 处理。
- `session-breakdown` / `resources-tree`：日历热力图 / 用量比例渐变依赖**连续色阶**（任意 RGB 或 256 色随数据变化），theme 仅有离散语义色、无连续色阶 API，属「数据可视化热力图」豁免。门禁脚本 `check-tui-compliance.ts` 的 `EXEMPT_FILES` 与此处保持一致。

### 2. 边框范式统一：纯横线，无角无竖线

所有 TUI 覆盖层统一为**上下纯横线边框**，废除 `┌┐└┘` 方角、`╭╮╰╯` 圆角与左右竖线 `│`：

```text
── 插件名 ──────────────────   顶边框：`── ` + 插件名 + ` ` + 横线填满（名字从第 3 格起）
    > 选中项                    内容（无左右竖线）
      普通项
 ───────────────────────────   内部分隔线：左右各缩进 1 格
    ↑↓ navigate · Enter         footer
────────────────────────────   底边框：纯横线填满
```

对应代码模式：

```ts
topBorder = '── ' + 插件名 + ' ' + '─'.repeat(填满);
separator = ' ' + '─'.repeat(填满 - 2) + ' '; // 左右各缩进 1 格，与顶边框形成层次
bottomBorder = '─'.repeat(填满);
```

**理由**：去掉竖线 = 去掉 `rightPad` 对齐计算 = 消除一整类「右边框错位」bug；去掉角 = 方角/圆角之争自然消失；
内部分隔线缩进 1 格使「面板边界」与「内容分隔」视觉可区分（纯横线若不缩进会与顶/底边框糊在一起）。

### 3. 竖线保留例外

`pi-session-tree` 的**树形 gutter 竖线**（树节点缩进的 `│`）是树结构本体，**不在迁移范围**。
迁移时只改「边框盒」的竖线，不改「树形缩进」的竖线。SelectList 等 pi-tui 内置组件内部的竖线由组件管理，不在此列。

### 4. 验收三层（取代「跑一遍人工看」）

每个 TUI 改造切片按三层验收，缺一不可：

| 层                  | 手段                                                       | 验证内容                                                             |
| ------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| ① headless snapshot | `renderToSnapshot` + `assertWithinWidth` + `dispatchInput` | 机器断言：2+ 宽度不超宽、边框对齐、按键后状态切换正确                |
| ② e2e 加载          | `tui-expect.smoke.test.sh`（PTY）                          | 扩展加载不崩、命令可触发；不验证 overlay 视觉                        |
| ③ 人工 REVIEW       | `[REVIEW]` 标记                                            | 边框/颜色/交互的最终视觉效果——PTY 无法可靠还原 overlay，必须人工确认 |

## 权衡

| 方案                                  | 结论                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| A. 保留竖线，统一方角（原 §7.5 路线） | 拒绝：竖线是「右边框错位」bug 的根源，为一点「闭合边界」视觉付出持续对齐成本不划算 |
| B. 纯横线无角（本决策）               | 采纳：去掉最大 bug 来源，代码量最小，边界仍可识别（顶边框嵌名 + 分隔线缩进）       |
| C. 连分隔线缩进都去掉                 | 拒绝：纯横线若不缩进，顶/底边框与内部分隔线视觉无法区分，层次糊掉                  |
| D. 全禁箭头（含 `↑↓`）                | 拒绝：需改几乎所有扩展 footer，工作量巨大，且单宽箭头无崩溃风险                    |

## 后果

- **正向**：字符白名单给「无 emoji」一条可执行的边界；纯横线边框消除对齐 bug 来源；三层验收让视觉回归可机器断言。
- **负向**：需迁移 6 个有角扩展 + 1 个纯竖线盒（见 ticket 04-10）；`tui-design-principles.md` §7 边框章节需改写以匹配新范式。
- **注意**：白名单只约束 Pi TUI 渲染路径；tmux 状态栏、通知文案、日志文本不受限。若未来终端对箭头宽度产生变化，需回查此 ADR。
