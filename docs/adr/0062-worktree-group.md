# ADR-0062: worktree 组——显式花名册与批量创建/合并/同步

**决策**：pi-worktree 引入**组（Worktree Group）**为一级概念——一份**显式声明的固定花名册**（组名 + 目标分支 `baseRef` + 成员列表 + 合并策略 + env 策略），随**仓库**声明（`<repoRoot>/.pi/extensions-data/pi-worktree/config.json`），支撑三个批量动作：**组创建**（只补建缺失成员）、**组合并**（按花名册顺序逐成员 `rebase → squash merge → 提交`，fail-fast + 可续跑）、**组同步**（成员对齐到目标分支）。批量范围**一次选定**后，后续所有步骤对这批成员**共用同一策略**。TUI 是主入口（溶进现有 switcher），命令 `/worktree group <action>` 是等价辅助入口。术语定义见 `CONTEXT.md` 的 `Worktree Group` 及相邻词条。

## 动机与实测事实

插件已有能力（创建 / 切换 / 合并 / 变基 / 同步 / 清理）全部是**单成员**语义，本仓库的固定工作流靠仓库外脚本 + 手工命令维持：

| 事实                     | 数据                                                                                                                                                                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 两套并行机制             | `scripts/recreate-worktrees.sh`（销毁重建 6 个 worktree）+ AGENTS.md 手工 `git checkout dev && git merge --squash wt/xxx`，插件完全不知道这 6 个的存在                                                                                        |
| 插件创建基点写死         | `createWorktree`：`git worktree add -b wt/<name> <path> origin/<defaultBranch>`（`lib/worktree.ts:55`）→ **无法从本地 `dev` 开分支**                                                                                                          |
| 插件合并落点写死         | `merge` 默认 target `'main'`、strategy `'merge'`（`handlers.ts:1237`、`lib/ui.ts` 调用处）→ 与本仓库 squash→`dev` 流程相反                                                                                                                    |
| 基点错配（本地 vs 远端） | 本地 `dev` 领先 `origin/dev` **16 个提交**；`execRebase` 在远端存在时 `fetch` + rebase 到 `origin/<b>`                                                                                                                                        |
| env 复用现状不齐         | `security` 用 `symlink` → `node_modules/@zenone/pi-logger` 解析到**主仓库**源码；`context`/`verification` **无 node_modules**（跑不了 `npm test`/`tsc`/`prettier`）；`bugfix`/`observability`/`tool` 为 `cp -al` 实目录（解析正确、磁盘共享） |

## 决策清单

| #   | 决策                                                                                                                                                                              | 依据                                                                                                                                                                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 组 = **显式声明的固定花名册**，不做「从 git 现状隐式推导成员」                                                                                                                    | 隐式集合会把无关实验分支扫进目标分支；且 `baseRef`/顺序/策略无处承载                                                                                                                                                                                               |
| 2   | 声明存 **pi-config 仓库级**（锚 `<repoRoot>`，见 ADR-0061）；**分节读改写**；`groups` 只在仓库级有效（用户级出现则 warn + 忽略）                                                  | 组内每项都是仓库事实；`save()` 整体写入该级文件，不写分节会跨级泄漏                                                                                                                                                                                                |
| 3   | 目标分支由 **`baseRef` → 解析链**得出，**禁止写死分支名**；「主检出」标识与分支名字符串**解耦**                                                                                   | `'main'` 现同时是 sentinel 与分支默认值（12+ 处），在本仓库默认分支 `main`/集成分支 `dev` 下互相遮蔽                                                                                                                                                               |
| 4   | **组创建**：只补建尚无 worktree 的成员（已存在者一律不动）；`wt/<name>` 分支已存在则复用；env 策略一次应用全批                                                                    | 创建与同步是两件事，拆开避免「创建偷偷改既有成员」                                                                                                                                                                                                                 |
| 5   | **组合并**：按花名册声明顺序，逐成员 `rebase 到 baseRef` → `merge --squash` → 提交；N 成员 = N 个提交                                                                             | 对齐 AGENTS.md「1 特性 = 1 提交」；冲突落在 rebase 阶段（有 `continue`/`abort`），不在 squash 阶段（squash 冲突只能回滚）                                                                                                                                          |
| 6   | 失败模型：**fail-fast + 可续跑**；**禁止跳过失败成员继续**                                                                                                                        | 跳过会合入引用不存在代码的提交且 git 不报错；已完成的 1..i-1 是独立提交，回滚无意义                                                                                                                                                                                |
| 7   | **范围一次选定**：候选 = 本次动作真正作用的对象集合；不适用的成员**保留显示为灰显上下文**                                                                                         | 用户指定；灰显比静默过滤有信息量                                                                                                                                                                                                                                   |
| 8   | 守卫：目标检出**不得处于 merge 进行中**（硬拒绝）；脏成员**显示但不可选**，执行层同样拒绝。主检出的未提交改动**不作拒绝理由**（`execMerge` 内部 stash/pop，不污染提交）           | 实测：绕过 `execMerge` 直接 `merge --squash` 会把暂存内容卷进提交，但插件路径先 `stash push` 再合并、末尾 `stash pop`，暂存改动原样保留（回归用例见 `worktree-group-ops.test.ts`）；把脏检出作为硬拒会拦住「主检出有在途改动」这一正常状态；未暂存脏文件不阻止合并 |
| 9   | **收尾对齐**两阶段：① 逐成员合入成功后**立即** `reset --hard <当时的目标分支>`（必需、自动）；② 整批完成后**再问一次**是否统一对齐到最终目标分支，**只列本轮已合入成员**          | 实测：不对齐则下轮 rebase 重放已 squash 的内容会**冲突**；逐成员对齐使各成员基线版本不同，需一次统一收口                                                                                                                                                           |
| 10  | env 复用策略 **默认 `copy`（`cp -al` 硬链接）**；`symlink` 仍可选，但对 `file:` 本地依赖**必须警告「解析到主仓库源码」**；选择处**必须展示各策略的空间占用与使用优劣**            | 实测：`cp -al` 下 `@zenone/pi-logger` 解析到**本 worktree** 源码且磁盘共享；`symlink`（绝对链接）解析到**主仓库**                                                                                                                                                  |
| 11  | TUI：**溶进现有 switcher**，一级列表分 `Groups` 段与 `Worktrees` 段；组行 → 二级组菜单；键位语义复用；选中 worktree 时行为不变；候选多选复用 `MultiSelectPanel`；**不新增快捷键** | 一级列表本就是工作区导航，组是工作区集合；改动面最小                                                                                                                                                                                                               |
| 12  | 命令面：`/worktree group <action>`（`new`/`edit`/`delete`/`list`/`create`/`merge`/`sync`），支持带参直接调用；**TUI 为主入口**                                                    | 用户指定「平常用命令少、更多是 TUI」                                                                                                                                                                                                                               |

## 被拒方案

- **隐式成员集**（`merge --all` / 所有 `wt/*`）：把无关实验分支扫进目标分支的风险 + 无声明位置承载策略。
- **先集成后一次合入**（临时集成分支把 N 个成员合起来再一次合入）：丢「1 特性 1 提交」的归属，出问题时无法按特性回退。
- **跳过失败成员继续合并**：静默产生引用不存在代码的提交。
- **事务性全有或全无**（任一失败回滚目标分支）：已完成的成员是**独立且正确**的提交；且成员侧 rebase 已发生，回滚不完整。
- **`symlink` 作 env 默认**：对本仓库（自身即 `@zenone/*` 源码）静默测错代码。
- **用户级组 + `repoKey` 隐式过滤**：只能换来「一处集中编辑」，却引入必须维护且易失配的 key（无 remote 走路径 hash）；跨仓库复用应走显式「导入」而非隐式作用域。

## 验证要求（语义级；仅「无报错 / 退出码」不算）

- **vitest（headless）**：目标分支解析链；声明校验（用户级 `groups` → warn + 忽略）；候选集合计算（不存在 / 无提交 / 脏 三类成员的归类）；**分节读改写不跨级泄漏**；收尾对齐的范围筛选。
- **e2e（真实 Pi，仅 mock LLM）**：
    1. 组创建补建缺失成员 → 断言 worktree 与 `wt/<name>` 真的存在、基点 == `baseRef` 本地 ref；
    2. 组合并两个有提交成员 → 断言目标分支多出 **2 个** squash 提交、两个成员已被对齐、**未触碰远端**（无 fetch、无 push）；
    3. 人为造冲突 → 断言**停在冲突态**、目标分支只有前 i-1 个提交、`continue` 能续跑剩余成员；
    4. 脏成员不可选 → 面板文本断言 + 绕过面板的执行层拒绝；
    5. 主检出的已暂存改动**不被卷进** squash 提交、合并后仍保持暂存；目标检出处于 merge 进行中 → 硬拒绝且**不产生提交**。
- **④/⑤ 的分层落点（2026-10-19 定）**：④ 是守卫类属性，两段语义都落在 headless——面板文本/不可选见
  `test/vitest/extensions/worktree-group-tui.test.ts`（脏成员灰显、Space 无效），执行层拒绝见
  `test/vitest/extensions/worktree-group-ops.test.ts`（真 git，断言脏成员被跳过）；不再补 e2e。
  ⑤ 保留一条真机 e2e（数据安全面，`test/e2e/extensions/worktree/tui-expect.smoke.test.sh` 的
  staged 用例），headless 回归为 `worktree-group-ops.test.ts` 的「已暂存改动不会被卷进 squash 提交」。
- **过程日志**：批量执行逐成员输出 `STEP_BEGIN`/`STEP_OK`/`FAIL_MARKER`，落 `.pi/logs/pi-worktree_*.log`（遵守 `docs/e2e-performance.md`）。
