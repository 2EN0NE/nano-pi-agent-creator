# ADR-0051: 成员启动参数（默认豁免权限门）

- 状态：**已接受**（2026-09-14 grilling 收敛；落地票见 `.scratch/member-launch-args/issues/`）
- 相关组件：`extensions/auto/org`（成员登记、唤醒、看板成员面板）、`@zenone/pi-config`（org 插件配置）；`extensions/security/permission-gate`（被豁免方，本轮**不改**，见 `D6`）
- 延伸：**修订** ADR-0040 `D1`（唤醒命令行形态）；承接 ADR-0048（唤醒入口）、ADR-0039 `H1`（人类操作台身份）、ADR-0045/0047（可观测与面人通道）、ADR-0025（permission-gate 危险分级）
- 术语：`launchArgs`（成员启动参数，见 `CONTEXT.md`）

## 背景

### 事故（2026-09-13 23:31 → 00:25+，真实 UAT）

人类派活给 `worker-b` → org 用 tmux 拉起 `pi -a --session-control` → 成员自主干活约 2 分钟后**直连外网全部失败**（`fetch_content` fetch failed；`curl https://x.ai/bot`、`https://docs.x.ai/...` 均 `HTTP 000` + `exit 28`）→ 它转而探测本机可能的代理端口，发出含 `curl … -o /dev/null …` 的一条 bash → **被 permission-gate 判为危险并弹出确认树** → tmux 会话里**无人应答** → **无限挂起**（会话文件自 23:33:09 起零写入，至 00:25 已 52 分钟，进程仍存活、账本停在 `invited`、org 侧零信号）。

事故当刻的 `permission-gate` 日志只有一行 `Config loaded: enabled=true, dynamicPolicy=true`（该成员进程启动时的配置加载），**没有任何"等待确认中"的记录**。

### 三个根因（均可复现，非推测）

1. **门禁两条判定路径不一致**：tree-sitter（warm）对「无害设备文件」已正确豁免（`BENIGN_DEVICE_PATHS`：`/dev/null`、`/dev/zero`、`/dev/stdout`…），但退化分词器（cold）在提取路径时把 `$(curl … -o /dev/null …)` 的路径取成 `/dev/null);`（尾随符号未清洗），精确匹配失败 → 前缀匹配到系统目录 `/dev` → 判 `system-dir-read`。
   同一条命令实测：**cold = `warning/system-dir-read`（需确认）；warm = `null`（放行）**。命中叶子是 `do code=$(curl … -o /dev/null …)`（门禁按 `;` 拆成的第 5 片叶子），与事故弹层里的叶子列表逐条对应。
2. **门禁确认没有出口**：`await Promise.race([tuiDecision, pending.result])`（TUI 与外部通道两条路径）**均无超时**，全模块没有 timeout/TTL/expire；唯一的无人值守降级是 `!ctx.hasUI`（print 模式直接 block）。tmux 里 `hasUI === true` → 无限等按键。
3. **成员进程默认带着门禁**：门禁配置按 **cwd** 分层解析，人类在本仓有项目级 `enabled: false`（所以人类从未察觉），而成员 cwd 是普通工作目录 → 落到内置默认 `enabled: true`。这条不对称是"人类没被拦、成员被拦"的全部原因。

### 与本次决策的关系

根因 1、2 属 `permission-gate` 自身缺陷；本轮**选择不修**（`D6`），改由「成员默认不带门禁」在这次事故的路径上兜底。根因 3 说明兜底必须**默认生效**：成员由代码拉起，人类不在场，无法临场应答。

## 决策

### D1 成员启动参数是**成员级**领域数据

存于该 org 的登记文件 `~/.pi/org/<org>/org.json` 的成员记录（`launchArgs`），**一个成员一份**。

- 备选：org 级（一份大家共用）、org 级默认 + 成员级覆盖。**均否**：需求是"每个员工的启动参数"；两级会引入"哪一层算显式清空"的歧义，恰是"我明明删了它又回来了"这类体验 bug 的温床；org.json 是组织的登记文件，成员级字段随 org 一起被读取/归档/history 留痕，位置天然合适。

### D2 默认值来自 org 插件配置，**加入组织时写入**成员记录

- 默认值在 `@zenone/pi-config`（org 插件，用户级 `~/.pi/agent/extensions-data/org/config.json`）中声明，初值 `--no-permission-gate`；
- **`join` 时**把该默认值写入成员记录的 `launchArgs`；此后**唤醒只读成员字段**；
- **记录里没有 `launchArgs` ⇒ 不加任何参数**：不做历史回填、不做唤醒期兜底（"没有的就没有"）。

取舍：默认值改只影响**此后加入**的成员，已加入的各自一份。这是有意的——同一组织内不同成员可能各有起法，且"改默认"不追溯才可预期。

### D3 值语义＝**纯追加**到固定核之后

拼装恒为：`pi <prefixArgs> -a --session-control [--session-id <上次>] <launchArgs>`。

- 固定核（`-a`、`--session-control`、`--session-id`）**不进可编辑串、不校验**：`--session-control` 是"在岗可收发成员消息"的命脉（socket 建不起来 = 被唤起了却在岗不可达），不该给一次误删的机会；
- `launchArgs` 按空白切分，**支持成对引号**（`-e "/path/with space/x.ts"`）；引号不配对 → 保存时报错并保留原值；
- 空串/全空白 ⇒ 不加任何参数（这就是"删除默认项"的落地形态）。

备选：可编辑完整参数（含固定核）、追加 + 黑名单校验。**均否**：前者把命脉交给可编辑文本；后者是在猜用户意图——既然是追加语义，重复写固定项属用户选择，org 不替他判错。

### D4 修改权＝**仅人类操作台**，成员视角隐藏

判据沿用现成信号：打开看板的 cwd **不在本 org 名册**（`meName === ''`）⇒ 人类。

- 成员视角**隐藏**该操作；其它入口一律拒绝并说明；
- 留痕 `launchArgsUpdatedAt`；
- **本约束不是安全边界**（cwd 可伪造：任何 agent 在非名册目录跑 pi 即可冒充人类），只是**防误触 + 身份一致**。真正的边界是"成员本来就有 bash（等同任意代码执行）"，因此启动参数不构成权限提升。

备选：仅负责人（chief）可改、不加限制。**否**：看板里更"重"的动作（踢退成员、转移负责人、改自动唤醒）本就无身份门，只给启动参数加门会造成"同一操作台有的动作要身份有的不要"的割裂。

### D5 两条启动路径的默认值必须一致

org 唤醒（自动唤醒 / `org_wake` 工具 / 人类按唤醒键，三者共用同一实现）与**文档、技能里教授的手工启动命令**都带同一默认参数。

理由：手工启动同样是**无人值守**形态（人敲完命令就离开，成员自己在那儿干活，见 ADR-0040 `D1` 原话），且它是文档教的主路径。只改唤醒路径会让默认值变成"半默认"——同一个组织里两种行为，排障时最难猜。

### D6 本轮**不修** `permission-gate` 的两处缺陷（记录在案，含复现与残余风险）

- 不修冷路径的无害设备豁免（`/dev/null` 等被判 `system-dir-read`）；
- 不引入确认超时/无人值守降级；
- 不把"无人值守"抽象成通用机制。

理由：本轮以 `D2`（成员默认不带门禁）在事故路径上兜底，控制改动面。

**残余风险（明示，不粉饰）**：

1. **任何仍带门禁的无人应答进程依然会无限挂起**——包括人类手工启动但未带该参数的成员、以及将来其它无人值守自动化（CI、定时任务）。表现为"既没执行也没失败、零回报"，与本次事故同型。
2. 有真实危险命中时（例如成员真的执行 `rm -rf`），无人值守下同样是"永久挂起"而非"拒绝 + 回报"。
3. 同类风险排查结论：有 `tool_call` 钩子的扩展里，**只有 permission-gate 会在 agent 循环中 await 按键**（`confirm-destructive` 只在 switch/fork 提示且 `!hasUI` 直接返回；`protected-paths`、`secret-firewall` 是直接 block 不等人）——即死锁面当前收敛在这一处，但一旦有第二个插件引入"确认后继续"的钩子，同型问题会复现。

将来要修时，最小起点是 D6-①：把无害设备豁免补进冷路径，并加"冷/热一致性"测试（同一批良性惯用法在两种解析器下判定必须相同）；其次才是超时语义（建议超时按**拒绝**处理，让成员"据实失败并回报"）。

### D7 让"当前用什么参数启动"可查

- 唤醒日志记录生效的完整 argv；
- 成员详情可见当前 `launchArgs`（与"编辑时必须展示现值"同一要求）。

### D8 参数被目标环境**不认识**时：去掉它重试一次，并据实告知（审查 07）

`--no-permission-gate` 由 `permission-gate` 扩展 `registerFlag` 注册，**不是 pi 内置**；pi 遇到未注册的
`--flag` 会直接终止进程（实测：`Error: Unknown option: …`、exit=1，唯一输出就这一行）。于是成员环境
若没装该扩展，唤醒命令会把成员**当场打死**（实测 1.6–2.3s），而 org 仍报成功。

决策：唤醒失败且输出指名"追加的某个参数不被识别"时，**去掉这些参数重试一次**（只影响本次拉起，
不写回成员记录），并把降级事实随结果回报（看板提示 + `/org wake` 回话 + warn 留痕）。

理由：能因该 flag 死掉，说明目标环境**没有注册它的扩展**——那道门禁本身也不在，去掉参数不削弱任何保护。
不采用的两条路：① 改由 permission-gate 读环境变量——env 会经 shell 泄漏、可能静默全局关掉门禁；
② 唤醒前探测扩展是否安装——npm/`-e` 等安装形态探不准，误判方向两边都糟。

### D9 「显式清空」与「从未设置」在记录里**不可区分**（有意）

两者都表现为字段不存在（`delete`），仅 `launchArgsUpdatedAt` 能看出"被改过"。不引入空串或
第三种状态：唤醒侧对两者的语义本来就一致（都不追加参数），多一个状态只会多一处要同步的分支。

### D10 采纳本特性顺带产生的三处超票行为（保留而非回退）

① 成员**列表**也能按 `p` 进编辑（票面只要求"成员详情内"）——列表是最常停留的位置，键位复用无额外代价；
② 成员详情展示"改于 <时间>"（票面只要求留痕）——留痕若不可见，排障时仍需翻文件；
③ CI 安装 tmux（为让唤醒类用例不 SKIP）——没有 tmux 的 CI 对"唤醒"这条主链零覆盖。

## 后果

- 成员默认不再被权限门拦住 → 事故路径消除，代价是成员侧少一层人工护栏（仍受 `protected-paths`、`secret-firewall`、`confirm-destructive`、`dirty-repo-guard` 约束）。
- 组织数据形态变化：`org.json` 成员记录多一个可选字段；`~/.pi/agent/extensions-data/org/config.json` 从"只看板界面偏好"扩展为"org 插件级默认（成员/公司相关）"，其文件头注释与相关 ADR 措辞需同步修订。
- 未决（本 ADR 不裁定）：org 侧对"成员在岗但长时间无进展"没有任何信号——本次事故里它表现为"52 分钟零动静却看不出异常"。是否加"疑似停滞"标注，留待单独决策。

## 验证

- 单测：默认写入（join 快照）、无字段 ⇒ 无参数、空串 ⇒ 无参数、引号切分与不配对报错、追加位置在固定核之后；
- 回归：清空后再唤醒仍不带该参数（跨唤醒持久化）；
- 端到端（真实 pi + 真实 tmux）：`/org wake` 拉起成员 → **参数到达进程**（桩扩展在 `session_start` 读 flag 落探针文件）、成员在岗（runtime 已注册）、3 秒后仍存活；目标环境不认识该参数时同理验证**降级重试 + 留痕**且成员记录未被改写（审查 08 重写了原用例：旧断言只看 argv，会把"启动即崩"判成通过；且真实 `pi` 会改进程标题，`ps -o command=` 读不到参数，故改用行为探针）；
- 唤醒可信（审查 06）：单一侧用"启动即退"的场景断言唤醒**失败并带回终端输出**，不再"尸体报成功"；
- 并发（审查 11）：人类改参数与成员在岗回写简档同时进行，两边改动都保住（per-org 写锁 + 可重入）；
- 看板：人类视角可见可改、成员视角隐藏、编辑屏在 2 种宽度下不超宽（headless TUI 测试）。
