# ADR-0060: 提升候选键的锚点 = 目标路径类别（不是目标路径）

**决策**：计数/提升的候选键**不由算法预设类别**，而是**由用户在爬升阶台上选定的层级**（①具体路径 ← 默认 ②父目录 ③已知临时区根；认不出的路径不提供③级）；算法只负责提供阶台与证据。命令名不参与泛化（不做「命令形状」档）。泛化必须搭配**路径出处**约束同时生效。

## 修正（提升走“用户在场”的路，不走判定路径）

初稿写的是「锚点 = `工具名 × 目标路径类别`」——它隐含“热路径上必须把路径分类判对，否则误放行”。修正为下列三条，**类目表从“判定闸门”降级为“爬升停靠站”**（可以永远不全、可随时加）：

1. **判定路径不做任何分类**，保持现有精确/保守行为，**不猜**。
2. **触发点在用户完成一次权限选择之后**，且必须**事件驱动**（`tool_result` / `turn_end` / `agent_settled`）——不能用定时器（本仓 AGENTS.md 坑 #13：扩展运行时 `setInterval`/`setTimeout` 回调不执行）。
3. **提示不阻塞 agent**：用 `ctx.ui.notify()` / `setStatus()` / `setWidget()`；细节确认由用户主动打开 overlay（`custom(..., {overlay:true})` 会抢焦点，不得在判定路径里 `await`）。

**阶台**（默认停在第 1 级）：

| 级  | 停靠站                      | 备注                                                              |
| --- | --------------------------- | ----------------------------------------------------------------- |
| 1   | 具体路径                    | **默认选项**                                                      |
| 2   | 它的父目录                  |                                                                   |
| 3   | 已知临时区根                | 实测只 3 条：`/tmp`、`<项目>/.pi/tmp`、`~/.pi-lens`；认不出不提供 |
| —   | ~~工具级~~（`rm` 任意目标） | **不给**：跳过“临时脚手架”语义，风险不换收益                      |

**为什么阶台不是纯词法爬升**：6 个 worktree 的路径在 `.pi/tmp` 之上除了 `…/nano-pi-agent-creator-worktrees/` 没有共同祖先，泛化到那里毫无意义——所以需要**命名的停靠站**（`<项目>/.pi/tmp` 把 6 个 worktree 归成“同一个项目的临时目录”）。

## 问题：现有三维键里，目标泛化轴锚错了对象

现有键为 `cmd:<整条命令>` / `tool:<工具名>` / `dir:<目标目录>`（阈值 2 / 3 / 4）。其中只有 `dir:` 是目标泛化轴，而它锚在**目标的父目录**：

- `rm -rf /tmp/probe-1234` → `dir:/tmp` ✔ 可累积
- `rm -rf "$T"` → **变量静态求不出值 → 父目录也求不出 → `dir:` 轴完全失效**

而 rm 类拦截里**变量间接占 54%**。这正是 `/tmp` 与 `$VAR` 两类痛点最重的原因——**恰好是 `dir:` 够不着的两类**。

## 数据依据（59 条含变量 rm 的实测）

| 归类路径                                                  | 条数 | 占比 |
| --------------------------------------------------------- | ---- | ---- |
| 命令内字面路径片段（`$R/.pi/tmp/x`、`$PWD/.pi/tmp/dbg3`） | 14   | 24%  |
| 命令内 `mktemp -d`（模板静态可判 → 临时区根）             | 12   | 20%  |
| 命令内字面路径（`~/.pi-lens/...`）                        | 4    | 7%   |
| 命令替换，片段可判                                        | 2    | 3%   |
| 变量未在命令内绑定（需**会话级变量账本**，非猜测）        | 25   | 42%  |
| 运行时求值，不可判                                        | 2    | 3%   |

两条关键读数：

1. 阶梯 ①-③ 可覆盖约 **97%**；「变量未在命令内绑定」不等于不可判，只是需要跨命令的变量账本。
2. **能归类的目标 100% 落在 `/tmp` 或项目内 `.pi/tmp`**（变量名 `SB` / `tmp_root` / `test_home` / `bench` 全是「临时沙箱」语义）→ **变的是值，稳定的是来源**。

## 为什么安全：泛化必须配出处

单独把匹配放宽到「类别」等于「允许删 `/tmp` 下任何东西」（包括别人的）。安全网是 ADR-0025 的**第四轴（路径出处）**：泛化后的规则**只对「本会话创建过的」路径自动放行**。

> **泛化解决「记不住」，出处解决「泛化后越界」。** 二者配套，不是二选一。

## 排除的档位

| 档  | 锚点                      | 排除理由                                               |
| --- | ------------------------- | ------------------------------------------------------ |
| A   | 目标父目录（＝现 `dir:`） | 对 54% 的变量目标失效                                  |
| C   | 命令形状（连命令名泛化）  | 把 `rm` 与 `mv` 混同；痛点在目标不在命令，风险不换收益 |

## 对既有文档的修正

`CONTEXT.md` 的「路径出处」原写「不覆盖 `$(mktemp -d)` 这类运行时求值的变量」——**该说法是错的**：`mktemp -d` 的模板 `${TMPDIR:-/tmp}/tmp.XXXXXXXXXX` 是静态可判的，归类为 临时区根即可。已改写为 ①-④ 的解析阶梯。

## 补充（出处条件的形态：挂在规则上，默认勾选）

泛化到台阶第 2/3 级后产生的规则，**必须**挂上「**仅限本会话创建的路径**」这一条件。落地形态：

```text
规则 B:  rm → /tmp/**   [条件: 仅限本会话创建的路径]
```

- **默认勾选**，且在确认卡片上以勾选项可见（`[x] 仅限本会话创建的路径`），用户可当场取消勾选去放宽。
- **失败方向必须是失败即拒绝**：识别不出创建来源时**退回弹窗**，不猜。
- 可行性依据：解析阶梯（见上文）对本仓 59 条含变量 rm 覆盖约 97%。

**为什么不让用户干脆选无条件（A）**：条件 B 保护的是**未来**——三个月后别的 agent 在 `/tmp` 跑别的任务时，B 不会替它放行；而 A 的失败方向是误放行（不可逆）。

## 收缩（锚点 = 目标根；废弃分类学）

读判定链路时发现一个推翻前述前提的事实：**`checkThreshold` 是 OR 语义**（`index.ts`：`const pass = passing.length > 0`）。三个维度（cmd 2 / tool 3 / dir 4）**任一达标即放行**。

推论三条：

1. **机制早已泛化到「工具级」**：`tool:rm ≥ 3` ⇒ 信任范围内**任意目标的 `rm`** 一律自动放行。所以「目标常变 → 记不住」这个前提**对 rm 不成立**——变量目标由 tool 维度兜住（数据里 `rm → $VAR` 有 22 次 auto 即此）。
2. **摩擦的真实来源是 `isInScope` 前置门**，不是目标锚点：目标在项目外（`/tmp`、`~/.pi`）时计数照常累积，但阈值检查**连执行机会都没有** → 永远问。
3. **本 ADR 原设计的「目标路径类别 + 分类学」是在解不存在的问题**，还引入了「必须在热路径判对」的风险。

**收缩决定**：

- 锚点从「**路径类别**」降为「**目标根**」。台阶（①具体路径 ← 默认 ②父目录 ③目标根）保留，但**台阶顶层是「根」，不是「类别」**——不需要分类学。
- 判定路径**不做任何分类**，人看具体例子确认要不要信任这个根。
- 安全性不再依赖分类正确，而依赖**出处条件**（仅限本会话创建的路径）。
- **出处条件由「可选安全网」升级为「扩面后唯一的护栏」**：一旦把 `/tmp` 纳入范围，现成的 `tool:rm ≥ 3` 立刻会放行**任意** `rm` 到 `/tmp`（包括别人的）。没有出处条件，这就是个坑（见 ADR-0059 的补充）。
