# 全量命令审计与分层存储

**决策**：permission-gate 对**每次命令执行（全部工具调用，不只被拦截的）**生成唯一 ID 并完整记录，作为审计回溯、拦截强度回检、以及未来智能自适应算法的语料。

**存储分三层，生命周期各不同**：

| 层                        | 内容                                                                 | 格式                                       | 生命周期               |
| ------------------------- | -------------------------------------------------------------------- | ------------------------------------------ | ---------------------- |
| 审计日志（audit log）     | 每次命令执行的完整记录（ID、时间、工具、命令、级别、决策、命中维度） | JSONL 按天分片（`audit/YYYY-MM-DD.jsonl`） | 默认保留半年，滚动清理 |
| 放行规则（approval rule） | 自适应放行沉淀的信任规则（三级：会话/项目/用户）                     | 按 pi-state 分层                           | 永久                   |
| 配置（config）            | pattern 清单 + 级别标注 + 阈值                                       | 按 pi-config 双层                          | 永久                   |

**为什么 JSONL 按天分片**：现有 `approvals.json` 是单 JSON 文件（实测已 2.3MB / 5136 条），每次写入需整读整写，随条目线性变慢。JSONL 分片改为 O(1) 追加，且按天分片使"保留半年"退化为"删除 180 天前的分片文件"，无需逐条裁剪。

**空间预估（实测基准）**：近 38 天全量工具调用 50853 条（日均约 1338，含开发期测试会话），单条精简记录约 250–300 字节。按上界估算半年约 60–100MB，对比 sessions 目录 707MB 属完全可控量级，无需担心膨胀。

**为什么全量而非仅拦截**：仅记录被拦截的操作无法回答"哪些被放行的其实该拦"——这正是分析 tab 与未来智能算法的核心输入。全量 + 唯一 ID 使每一条命令执行都可被外部通道凭 ID 引用与确认。
