# ADR-0047: 扩展告知通道分层——面向人 vs 面向模型

- 状态：**已接受**（2026-09-12；D1–D3 待落地）
- 相关组件：所有扩展（尤其 `extensions/auto/org`）
- 姊妹决策：ADR-0046（org 上岗自决）
- 术语：见 `CONTEXT.md`（多 agent 框架节：告知通道 / 卡片）

## 背景

pi 的 `pi.sendMessage({ customType, display })` 在进模型前会被 `convertToLlm` 统一改写：

```js
case "custom": return { role: "user", content: ..., timestamp: m.timestamp };
```

即：**自定义消息一律变成 `role:"user"` 进上下文**；`display` 只控制 TUI 是否渲染，**没有**「只给人看、不喂模型」的开关。后果：

1. 用 `sendMessage` 发给人看的提示（状态告知、可发现性提示）＝ 每次请求都多一条 user 消息 → 持续占用上下文、与人类真实输入混在同一通道、稀释指令。
2. 且这类消息**随会话持久化**，事后无法区分「这是系统提示」还是「用户说的」。

## 决策

### D1 按受众选通道

| 受众                                   | 通道                                                                                      | 进 LLM 上下文 |
| -------------------------------------- | ----------------------------------------------------------------------------------------- | ------------- |
| **人**（状态、可发现性、瞬时提示）     | `ctx.ui.setStatus`（常驻状态栏）、`ctx.ui.notify`（瞬时 toast）、`custom` overlay（交互） | **否**        |
| **模型**（任务、对账、简报、来源声明） | `pi.sendMessage` 卡片、`before_agent_start` 静态块、`input` transform 动态块              | **是**        |

### D2 判据

> **这条信息是给人看的，还是模型必须知道的？**

只给人看的 → 禁止走 `sendMessage`。拿不准 → 默认走状态栏（人看得到、零上下文成本）。

### D3 卡片的门槛

面向模型的卡片（`sendMessage`）**每条都计入上下文成本**，且随会话累积。因此：

- 仅在岗/必要时发（现例：`org-inbox` 离线补投、`org-startup` 启动对账、`org-handshake` 惰性催办——均在岗门控下才发）。
- 新增「提示性」卡片前须权衡；能用状态栏表达的，不进卡片。

## 后果

- org 的 `org-off-duty` 由卡片改为状态栏（ADR-0046 D5）——这是本条决策的第一个落地案例。
- 后续「可发现性」需求默认走状态栏，而不是「再发一条提示卡片」。
- 已知例外：**成员消息**（`customType:session-message`）必须是 user 角色才对（它就是发给模型的内容，ADR-0044），不在本条约束内。
