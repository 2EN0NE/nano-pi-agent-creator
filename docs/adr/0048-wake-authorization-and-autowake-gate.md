# ADR-0048: 唤醒授权与自动唤醒门禁

- 状态：**已接受**（2026-09-13 grilling 收敛；落地票见 `.scratch/org-wake-authorization/issues/`）
- 相关组件：`extensions/auto/org`（工具与命令注册、成员生命周期、派发、看板）、`extensions/auto/control`（在岗前提）
- 延伸：**正式化并修订** ADR-0040 `D2`/`D3`（授权面与门禁语义）；沿用 ADR-0041「人类操作台永远可用」、ADR-0047「不静默 / 面人通道」、ADR-0045（自主闭环验证面）
- 术语：见 `CONTEXT.md`（多 agent 框架节：唤醒入口 / 自动唤醒开关（autoWake）/ 主动唤醒 / 显式唤醒 / 可感知状态）

## 背景

一次真实 UAT（2026-09-13 01:13–01:27）暴露：人类要求负责人 agent「唤醒任意一个成员，让他查点东西」，agent **全程既没派活、也没唤醒任何人**——它去读源码，最后试图写脚本直接调内部唤醒函数。

可复现的判定证据（非推测）：

- 负责人侧 org 日志：`01:25:55 在岗注册 / 上岗` → `01:27:55 未在岗`，其间**没有任何派发行**（派发成功必留一行）；
- 会话记录：工具调用只有感知类工具与读文件/搜索，**没有任何派发工具调用**；任务账本无新任务；
- 组织数据根 `runtime/` 为空、成员目录无日志 → **没有任何成员进程被拉起过**。

根因**不是代码 bug**，而是能力与入口的设计缺口：

1. ADR-0040 `D2` 已把唤醒权授给「人类 + 该 org 负责人 agent」，但 `D3` 只给了 agent 一条**隐式**路径（派活时自动唤醒），且被 `autoWake` 门住；
2. `autoWake` 的唯一写入口在**看板设置页**（只有人能用）——agent 既不能开，也没有任何显式唤醒动作；
3. 负责人技能只写「离线者会自动进收件箱不丢」，**没有「叫醒」这条路** → agent 据此认定"不用管"，继而自行发明路径（读源码、写临时脚本）。

## 决策

### D1 `autoWake` = 「自主 / 命令」唤醒的总门

- **开**：允许自主唤醒——派活时自动唤醒 + 显式唤醒动作（工具 / 命令）均可；
- **关**：**不存在任何自主或命令唤醒路径**（派活自动、agent 工具、人类命令一律不得唤醒），成员保持下线、任务落 **inbox 兜底**（不丢）。
- 开关表达的是「**不要自主叫他起来**」，**不是**「成员绝对不可被叫醒」；**只有人类**能改此开关（看板设置页）。

### D2 唯一例外：人类在看板的当面操作

人类在 TUI 看板对选中成员的当面操作（唤醒 / 睡眠）**不受开关约束**——依 ADR-0041「人类操作台永远可用」，否则会自锁。此例外与「命令受门禁」并存，故文档与提示**必须讲清这条不对称**（否则人会困惑"按键行、打命令不行"）。

### D3 agent 面新增显式唤醒动作（工具）

语义 = 「把人叫起来」：**幂等**（已在岗 / 已在拉起中则跳过）、**不改组织数据**、**不产生任务**。与"派活"分离——有些场景只需叫醒（问一句、临时协作、确认状态），不该被迫先建任务。

### D4 人类命令面提供同一动作

人类命令与工具**同实现、同门禁、同文案**，且**不要求在岗**（人操作台永远可用）。命令为脚本 / 非 TUI 场景提供一条路径。

### D5 唤醒权限限该 org 负责人

依 ADR-0040 `D2`：非负责人调用**据实拒绝**（"唤醒权限限本 org 负责人"），不静默隐藏。

### D6 门禁与失败一律据实回报，且不替 agent 打扰人

- 门禁拒绝、幂等跳过、拉起失败都要**说明原因与出路**（在设置页开启「自动唤醒」，或人对该成员按唤醒键）；
- 扩展**不主动**触达人（不代 agent 决定是否打扰人）——是否 / 如何请人由 agent 自己决定（依 ADR-0047）；
- **不隐藏能力**：门禁关闭时工具仍注册、调用即拒。静默隐藏会让 agent 无从知晓，再度自行发明路径（本次 UAT 的失败模式）。

### D7 留痕要求（可观测是排障前提）

- 派发路径每次都要记录 `autoWake` 状态与该分支决策（自动唤醒 / 只投 inbox）；
- 显式唤醒每次都要记录结果（已拉起 / 跳过原因 / 失败原因）；
- 拉起失败（目录不存在 / 解释器不在 PATH / 会话宿主不可用 / 起会话失败）**必须有 warn/error 级日志**——此前这些路径**零日志**，导致本次 UAT 只能靠"日志缺失"反推。

### D8 技能必须写明这条路与门禁

负责人技能要写清：存在显式唤醒动作、其门禁语义、以及**门禁关闭时必须向人明说**（不可静默降级成"我派了他上线再干"）。

## 后果

- **正向**：ADR-0040 `D2` 授予 agent 的唤醒权真正可行使；人类交代"叫醒某人"不再需要人肉启动进程；门禁语义单一（开关 = 自主唤醒总闸）；门禁与失败都有留痕，排障不必反推。
- **负向**：工具面 +1；「派活自动唤醒」与「显式唤醒」两条路径并存（靠日志与技能区分意图）；看板当面操作与命令的门禁**不对称**，需在文案/文档中持续解释。
- **明确不支持**：**「绝对保持下线（pin）」**。人要成员彻底不下来，手段是关掉 `autoWake`（挡住自主/命令路径）+ 不按当面唤醒键——这依赖人的行为，**不是强制隔离**（本仓库任何"只有人能做"的边界都只是政策边界：agent 有 bash 即可代按界面，同 ADR-0044「仅是声明，不构成防伪造」的口径）。
- **延期（另票，登记于工程 TODO）**：巡检清理阈值校准；控制通道超时→不确定路径的 e2e；e2e 占位符覆盖面。

## 验证

e2e 四例（**真实多进程 pi + 仅 mock LLM**）：

1. 开关开 + 派活 → 自动唤醒 + 投递 + 被唤醒成员**自主**处理并交付（补 ADR-0045 `A6` 未覆盖的另一半）；
2. 显式唤醒 → 后续派活送达；
3. 开关关 → 显式唤醒被拒 + 派活只落 inbox + agent 据实告知人；
4. **跨扩展防护（preset × org）**：preset 同时加载时，动态注册的 org 工具不被其"应用工具集"吞掉——断言同一会话里 fleet / wake / dispatch **三个工具都真的执行到**、报告了工具集的轮次里 org 工具集合恒等于 `ORG_TOOL_NAMES`、派活落账 + 门禁关只落 inbox + 「派活未自动唤醒」留痕。

> **第 4 例的由来（2026-09-13 真实 UAT 事故）**：`preset` 应用工具集时**整体覆写** `pi.setActiveTools()`，把后注册的 org 工具（含 `org_wake`）静默丢掉 → agent 调 `org_wake` 报 `Tool org_wake not found`，而 org 侧日志毫无痕迹（调用根本没到扩展）。org 自身 e2e 只加载 org + control 且 HOME 隔离，**结构上**看不到此类跨扩展干扰，故补此例。**推论**：任何"整体覆写活动工具集"的扩展都需同样的保护面；preset 侧还应有**与 org 无关**的通用用例（注册一个假工具后断言不被吞），本 ADR 只从 org 侧兜住该回归。
