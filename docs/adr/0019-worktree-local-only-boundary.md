# ADR-0019: pi-worktree 职责边界——本地 git 操作，远端 push 归用户

- 状态：已接受（2026-08-17）
- 相关组件：`extensions/meta/worktree`（pi-worktree v2）

## 背景

调研中发现：`merge`/`rebase-ff` 成功后的收尾流程仅提示用户手动 push
（`showPostMergeGuide`），无 push 执行能力。调研时考虑补齐 push 集成
（合并后自动询问 / 独立 push 命令），使"bash 零门槛闭环"更完整。

## 决策

**插件只负责本地 git 仓库操作。push / 远端发布归用户。**

- 不实现 push 集成（不新增 push 命令，不在合并成功后自动询问 push）
- 合并成功后的 guide 保持现状：提示用户自行 `git push`（或走 PR）
- 插件不自动推、不强推，不在任何命令中隐含远端副作用
- 远端操作（push、PR 创建、远程分支管理）属用户决策域：涉及认证、
  权限、远端分支策略，不应由插件代劳

## 权衡

| 方案                          | 行为         | 结论 |
| ----------------------------- | ------------ | ---- |
| A. 合并后自动询问 push        | 一键收尾闭环 | 拒绝 |
| B. 独立 `/worktree push` 命令 | 用户手动触发 | 拒绝 |
| C. A + B 都做                 | 覆盖最全     | 拒绝 |

用户明确：push 要用户自己做，插件只负责本地 git 仓库的事情。

## 后果

- **正向**：职责边界清晰——插件命令的全部副作用限定在本地仓库；
  避免自动 push 造成远端误发布风险。
- **负向/注意**：合并收尾需要用户多一步手动 push；未来如需求变化
  （如支持"push 前确认"），需重新评估本 ADR。
- **文档**：CONTEXT.md 已记录 pi-worktree 职责边界表（操作域归属）。
