# ADR-0053：人工干预在岗成员（中断与重试）

- **状态**：已定（决策收敛 2026-09-14；实现见 `.scratch/org-observe-and-intervene/issues/`）
- **日期**：2026-09-14
- **相关**：ADR-0040（在岗/忙碌与「感知与动作分离」）、ADR-0041（人类操作台永远可用）、ADR-0048（唤醒授权与门禁：动作的权限/留痕口径先例）、ADR-0051（成员启动参数）、ADR-0052（成员动态：观测面）

## 背景

人反馈（2026-09-14）：看到成员跑偏时**没有任何中间干预手段**——当前唯一动作是看板 `s 睡眠`（`requestStop`，**进程级**停，`board.ts:1741`），要么不动，要么把进程干掉（连带丢掉会话上下文）。人的真实流程是：

> 发现不对 → **先暂停** → 再决定：重派任务 / 重试 / （将来）回退到 `/tree` 某节点重新下指令。

`abort`（停当前轮、进程与会话都不动）与 `睡眠`（停进程）是**两种不同的"停"**，前者缺失。

## 事实（挂点已核实）

| 能力                            | 现状                                                                | 位置                                       |
| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------ |
| 停当前 loop（≈ 成员终端按 ESC） | control **已实现** `abort` → `ctx.abort()`                          | `extensions/auto/control/index.ts:602`     |
| org 侧 RPC 类型                 | 只有 `send \| ping \| get_message`，**没有 abort**                  | `extensions/auto/org/types.ts:248`         |
| 回退会话树节点                  | control 内**已用过** `sessionManager.rewindTo(entryId)`（压缩路径） | `extensions/auto/control/index.ts:739-744` |
| 从节点分叉                      | pi 扩展 API：`ctx.fork(entryId, { position })`                      | pi `docs/extensions.md:1172`               |
| 任务层重派                      | 账本已有 reject / handoff / 改派                                    | `extensions/auto/org/task.ts`、`board.ts`  |

## 决策

### D1：本批范围 = A（轮级中断）+ C（任务层重试/重派）；B（会话树回退/分叉）延后（已定，2026-09-14）

- **A**：看板对选中成员发 `abort` → 停止当前轮次，**成员留在原地待命**（进程/会话/记忆不动），人再决定后续。
- **C**：任务层的"重试 / 重派"——复用既有账本动作，仅补"重试"的语义（见 `D5`）。
- **B 不做**：会话树回退/分叉要新增两条 control 命令 + 看板选节点 UI，且先要定 `rewind`（丢弃其后分支）还是 `fork`（分叉保留原分支）的语义——**本批用过渡手段**：按 ADR-0052 `D7` 的提示 `tmux attach` 进成员终端，用 pi 自带 `/tree` 手动处理。**理由**：A 是"暂停"的最小完整切片且挂点现成；B 的语义未想清，硬塞会把票拆歪。

### D2：权限面 = 人类 + 该 org 负责人 agent（已定，2026-09-14）

- **人类**：看板对选中成员的中断键 + `/org abort <成员>` 命令面（**同实现、同文案**；命令面让 e2e 可脚本化）——依据 ADR-0041「人类操作台永远可用」。
- **负责人 agent**：新增工具（`org_abort` 或同类名），权限口径**照抄 ADR-0048 `D5`**——仅该 org 负责人可中断；非负责人**据实拒绝并给出路**（对齐 ADR-0048 `D6`：据实回报，不替 agent 打扰人）。
- **否决**"任意 agent"：权限放大且无审计视角。
- 风险注记：负责人可能在判据不足时误打断同伴。本批与 ADR-0052（成员动态）**同批上线**正是为此——先让它"**看得见**"，再给它"**动得了**"的能力；且中断是"停"不是"毁"（进程/会话/记忆都保留），可逆。

### D3：回执必需，但不做二次确认（已定，2026-09-14）

- **不做确认弹层**：中断轻量且可逆（进程/会话/记忆都保留，按错了重新派一次即可）。对比：`s 睡眠`是销毁性动作（杀进程）才需要确认。
- **回执必需**：看板通知行 + `/org abort` 回话 + 日志三处可见；失败同样据实回报（含原因与出路）。

### D4：留痕（已定，2026-09-14）

按 ADR-0048 `D7` 精神：中断与重试必须落日志——**谁**（人类 / 哪个 agent）、**对谁**、**动作**（abort / retry）、**结果**（成功 / 跳过原因 / 失败原因）。排障不得靠"日志缺失"反推。

### D5：C 的重试语义 = **重新投递**，不改账本状态（已定，2026-09-14）

**与代码事实核对后的修正**（初稿写"把参与者状态退回 `dispatched`"，与状态机矛盾）：

- **参与者状态机受保护**（`invited / claimed / delivered / returned / rejected / cancelled`，`task.ts:144-151`），**没有**"回到已派发"这一迁移。
- 中断只停**当前轮**：参与者与任务的归属都没变（通常仍是 `claimed`）→ **重试 = 把任务重新投递一遍**（附一行"上次中断/失败"说明），**不改任务编号、不动账本状态**；走既有投递通道（不在岗则落 inbox，任务不丢）。
- **该拒绝的三种情形据实拒绝并给出路**：任务已 `closed`（铁终态）→ 新开任务并引用；参与者已 `delivered` → 走**打回**（轮次 +1）；已 `stopped`/`rejected`/`cancelled` → 走**改派**。
- 重试事实由**任务历史事件（`retried`）+ 投递内容里的说明**承载；**不新增账本字段**（`attempts` 计数为升级路径）。
- 人面入口：看板任务详情对焦点参与者按 `t`（二次确认）；命令面 `/org retry <任务编号> [成员名]`。

### D6：中断不受「自动唤醒开关」约束（已定，2026-09-14）

`abort` 是"**停**"不是"**起**"：不唤醒任何进程、不改变成员在岗与否，与 ADR-0048 的唤醒门禁无关；人类操作台永远可用（ADR-0041）。**此条写死**，防后人误加门禁。

### D7：降级口径（已定，2026-09-14）

成员跑**旧版 control**（不认 `abort`）→ 看板与工具**据实回报**「该成员进程不支持远程中断（版本旧），可 `tmux attach` 后手动按 ESC 中断」，并**一次性 `warn` 留痕**（不每 tick 刷）。socket 不可连 / 超时同此口径：**绝不静默假装成功**。

## 备选与否决

| 方案                                | 否决理由                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| 用「睡眠」（杀进程）代替中断        | 丢会话上下文与未落盘的工作；"停一轮"与"停进程"是两种不同意图，人需要前者        |
| org 直接改成员会话文件实现回退      | 绕过进程内状态，必然与运行中的会话管理器冲突（本批不做 B，故不涉及）            |
| 给 agent 自主中断同伴的能力（本批） | 权限与门禁需专门设计（ADR-0048 同族问题）；先只做人操作台，避免一上来就放大权限 |

## 验证方式（tickets 阶段细化）

1. **vitest**：中断命令的构造与失败降级（socket 不可连 / 旧版 control / 超时）不改变四态；`D5` 重试语义的账本断言。
2. **e2e（真实多进程，仅 mock LLM）**：用 `MOCK_LLM_TOOL_CALLS`/长轮次构造"成员正在跑"的状态 → 发中断 → 断言成员停止且**会话未被破坏**（可继续接受新指令）；任务重试的账本终态。
3. **TUI（headless）**：键位与确认屏（若采纳 `D3` 确认）在多宽度下不超宽；回执通知行渲染。
