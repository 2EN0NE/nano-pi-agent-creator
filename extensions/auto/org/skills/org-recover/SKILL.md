# org-recover — 失联/卡死成员处置（仅人类执行）

**铁律**：agent 不得 kill 任何 pi 进程；本处置由**人类用户**下指令执行。

## 何时用

某 org 成员失联/卡死：派发消息一直没回应（离线收件箱堆积）、或在岗状态可疑。

## 处置步骤（人类）

### 1. 先确认对方状态

在任意 org 会话查看 `/org fleet <org名>`：

- 该成员「离线」= 进程没在跑 → 无需 kill；任务会进它的收件箱，等它下次启动补投（不丢）。
- 成员显示在岗但消息无回应 → 可能卡死。

### 2. 人工判定与终止

在**人类自己的终端**里，确认该进程确实是你要终止的那个（`ps -p <pid>` 核对路径/参数），然后：

```bash
kill -TERM <pid>      # 先温和终止
sleep 2
kill -KILL <pid>      # 仍未退出再强杀
```

不要用无参数 `pkill pi`（会误杀你自己的会话）。终止后该成员的运行时登记会由它的清理流程移除；若残留，重启该成员目录的 pi 会自动重新登记。

### 3. 恢复任务

- 该成员名下未交付的子任务回到任务池（若它已退出组织）或等它回来继续（若只是掉线）。
- 派发人可在 `/org my-tasks <org名>` 看到受影响任务，决定改派或等待。

## 边界

- 杀进程永远是人类动作，不写进任何 agent 工具。
- 若怀疑多个进程都失联，逐个核对 pid 后处理，别批量模糊匹配。
