# org — 目录绑定 agent 组织（人类操作台）

一台电脑一个数据根：**`~/.pi/org/`**（可用环境变量 `ORG_ROOT` 覆盖，测试/沙箱用）。
「公司」= 该根下的一棵数据目录树；「成员」= 绑定各自工作目录的 agent（成员目录与公司名无关）。
TUI 看板 `/org` 是人的操作台：查看/验收/踢退/负责人转移/公司 CRUD 都在这里完成，落账 `human@<目录名>`。

---

## 1. 数据文件位置（改名/备份/人工清理都看这里）

```text
~/.pi/org/
├── .trash/<公司名>-<时间戳>/    # 「删除公司」归档（可人工恢复，不物理抹除）
└── <公司名>/                    # ← 一家公司 = 这一棵目录树
    ├── org.json                # 花名册：name / chiefName / chiefDir / members[{name,dir,role,manifest}]
    ├── tasks/<任务号>.json      # 任务账本（含 `.org` 字段，公司改名时随迁）
    ├── history/<成员名>.json    # 成员离开档案（踢退/自退都保留；同名回归继承判断用）
    ├── runtime/<成员名>.json    # 在线/忙碌状态（成员进程运行时写）
    ├── inbox/<成员名>/          # 离线消息队列（成员下次上线补投）
    └── todo-map.json           # 与 todos 插件的投影映射（entry.org 公司改名时随迁）
```

> 成员工作目录**不在**这里——`members[].dir` 只是指向各成员自己项目目录的引用；公司改名不动它们。
>
> **TUI 界面偏好不在**这里：`sortNewFirst` / `annotate` 走 `@zenone/pi-config`，存用户级
> `~/.pi/agent/extensions-data/org/config.json`（历史 `~/.pi/org/.board.json` 已废弃、不再读取，见 ADR-0039 §H）。

## 2. 公司 / 成员 CRUD 操作矩阵

| 实体 | 操作     | 入口                                                    | 触及文件                                                                            |
| ---- | -------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 公司 | **C** 建 | `/org create <名>`、TUI 设置「新建公司」                | 新建 `<名>/org.json`                                                                |
| 公司 | **R** 查 | `/org orgs｜status｜fleet｜tasks｜my-tasks`、TUI 三视角 | 读整棵树                                                                            |
| 公司 | **U** 改 | TUI 设置「重命名公司」                                  | 目录 rename + `org.json.name` + 全部 `tasks/*.org` + `todo-map.json` 的 `entry.org` |
| 公司 | **D** 删 | `/org delete <名>`、TUI 设置「删除公司」                | 整树 → `.trash/<名>-<时间戳>/`（可恢复）                                            |
| 成员 | **C** 加 | `/org join <名>`、TUI 设置「加入公司」（用当前目录）    | `org.json.members`（+ 有历史时回归档案）                                            |
| 成员 | **R** 查 | TUI 成员视角、`/org fleet｜status`                      | `org.json` + `runtime/`                                                             |
| 成员 | **U** 改 | TUI 成员视角 `m` 负责人转移                             | `org.json`（两人 role + chiefName/chiefDir）                                        |
| 成员 | **D** 踢 | `/org leave`（自退）、TUI 成员视角 `d` 踢退（人类强制） | `org.json.members` 移除；**history 档案保留**                                       |

**保护规则**：负责人不可踢退（先 `m` 转移）；最后一名成员不可踢退；被指负责人直接上任、原负责人自动降为普通成员（人类强制，不可拒绝）。

**明确不做**：成员 `label/描述` 编辑（一次定死）；连历史一起删的「除名」——要彻底抹掉历史，请人工删除 `history/<成员名>.json`。

## 3. 公司改名：为什么要动这些文件

公司名是这家公司数据树的**目录名**（`~/.pi/org/<名>/`），因此改名 = 迁移自己这棵树，不涉及任何成员工作目录：

1. `<旧名>` → `<新名>` 目录整体 rename（同文件系统原子）
2. `org.json` 的 `name` 字段
3. `tasks/*.json` 每个任务的 `.org` 字段（`saveTask` 以该字段定位目录，硬引用，必须全量迁移）
4. `todo-map.json` 每条 `entry.org`

**注意**：成员侧存量 todos 文件里的 `org:<旧名>` 标签属派生展示，不自动刷新，任务重投影时自然更新。改名期间若有成员进程在线，其 `runtime/inbox` 写入可能落到旧路径——**建议成员离线时改名**（改名后成员进程重启即恢复）。

## 5. 人工清理路径

| 想做什么                   | 怎么做                                                    |
| -------------------------- | --------------------------------------------------------- |
| 彻底删除某成员的历史档案   | 删 `<公司名>/history/<成员名>.json`                       |
| 彻底删除某公司（不可恢复） | 删 `.trash/` 下对应归档目录                               |
| 恢复误删公司               | 把 `.trash/<公司名>-<时间戳>/` 移回 `~/.pi/org/<公司名>/` |
| 清空所有测试数据           | 删 `~/.pi/org/` 整个目录（会丢失全部公司与任务）          |

## 6. 看板 tab 语义：所属组织 / 排序 / 在岗点阵（ADR-0070）

`/org` 面板顶部那排组织 chip 有三个独立维度，**互不覆盖**：

| 维度         | 表现                       | 含义                                             |
| ------------ | -------------------------- | ------------------------------------------------ |
| **所属**     | 名字用正常色 / 压暗（dim） | 打开面板的**当前目录**是否登记在该组织成员表里   |
| **当前**     | accent + 加粗方括号        | 正在看的那一家（标题行 `── org:<名>` 也会写明）  |
| **在岗人数** | 名字后的**单格盲文点阵**   | 该组织此刻有几个成员在岗（与所属无关，单独着色） |

- **所属**的判据是**目录精确匹配**成员注册表，可能**多家**（同一目录可同时加入多个组织），也可能**一家都没有**。
- **所属随面板内动作立刻刷新**：新建 / 改名 / 加入 / 删除公司，以及**踢退自己**（把本目录成员移出）后立即重算（前两者会换掉 `ownOrgs` 里存的成员目录或组织名）；外部进程改注册表则需重开面板——`r` 只重算排序键，不重算所属。这四处动作也会**立刻重算在岗点阵**（否则当前 org 换了而点阵停在上一次的旧值，最长等一拍 4s）。
- **排序**：所属段在前（段内按该组织**最近派活**倒序），非所属段在后（按名字母序）。两段之间有一道 `│` 分界；**没有分界 = 没有所属段**。
- **一家都没有所属时**：除**正在看的那家**（仍 accent + 加粗，否则看不出在看谁）外全部压暗，并额外给一行 `本目录未加入任何组织`（只有一家组织时也给）——否则「全暗」会被误读成「全部不可用」。
- **在岗点阵**（只表示人数，不表示忙碌；上限 8，超出显示 `⣿+`）：

| 在岗 | 0   | 1   | 2   | 3   | 4   | 5   | 6   | 7   | 8   | >8   |
| ---- | --- | --- | --- | --- | --- | --- | --- | --- | --- | ---- |
| 点阵 | `⠀` | `⠁` | `⠃` | `⠇` | `⡇` | `⡏` | `⡟` | `⡿` | `⣿` | `⣿+` |

- `0` 是**空白盲符**（宽度与其它点阵一致），不是没渲染。
- **精度说明**：正在看的组织用权威判据（在岗注册 + socket 可连）；**其余组织用廉价判据**（在岗注册存在且其进程存活）——所以别家可能把「进程在但 socket 断了」算作在岗。切过去后立刻回到权威判据。
- 点阵**每 4 秒**随巡检刷新（与成员视角的四态同一拍）。

> 想人肉验证排序：在另一个目录 `/org join` 一个新组织，再往它派一条任务，然后回来看 tab 是否挪到前面（重排时屏幕会**按名字跟住**你正在看的那家，不会跳到别家）。

## 7. 成员进程生命周期（唤醒 / 睡眠）

| 想做什么                  | 怎么做                                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 看成员在不在岗 / 在干什么 | `/org` 看板 → 成员视角：行首圆点四态（暗空心=睡眠 / 空心=空闲 / 亮实心=工作中 / 实心=待验收）；`Enter` 看诊断行                                                                |
| 唤醒一个睡眠成员          | 选中该成员 → `w`（在注册 cwd 以 tmux 会话 `org-<公司>-<成员>` 拉起 `pi -a --session-control` + 该成员的**启动参数**（默认 `--no-permission-gate`，见下条），自动续接上次会话） |
| 让它睡眠（释放资源）      | 选中 → `s` → `y` 确认（tmux 托管走 `kill-session`，人类手工启动的走 PID）                                                                                                      |
| 直接看某成员在干什么      | `tmux attach -t org-<公司>-<成员>`                                                                                                                                             |
| 改成员的启动参数          | 成员视角选中 → `Enter` 进成员详情 → `p`（**仅人类操作台**；进入时先显示当前值，留空保存 = 删除该参数）                                                                         |
| 派活时自动拉起睡眠成员    | 设置 → 「自动唤醒（本组织）」开（存本组织 `org.json` 的 `settings.autoWake`）                                                                                                  |

- **权限**：唤醒 = 人类（看板）+ 该组织负责人（派活时按开关）；**睡眠 = 仅人类**（看板）。
- **续接**：睡眠前把当前会话 id 落到 `<公司>/last-session/<成员>.json`，唤醒时以 `--session-id` 续接同一会话。
- **自我豁免**：不能唤醒/睡眠**自己所在目录**（一目录 = 一员工）。
- **巡检**：看板打开期间每 4 秒刷新状态，**只读**（不唤醒、不杀停）；清理已死成员的残留 runtime——**进程仍存活的绝不清理**。
- **注册失效标注**：成员列表与 `org_fleet` 会对**注册目录已不存在**的成员额外标注 `[注册目录不存在]`。它与「睡眠」必须区分——睡眠可唤醒，而注册目录失效时**任何唤醒都会失败**（典型来源：历史 vitest 残留目录、目录被人工删除）。看到该标注请让该成员用现存目录重新 `/org join`，或从名册移除。
- **启动参数**：每个成员有一份「唤醒时追加的参数」（默认 `--no-permission-gate`，见 ADR-0051）——成员在 tmux 里无人值守，权限门的确认弹层没人应答会**无限挂起**，所以默认不带门禁。**只有人类操作台**能改（成员视角隐藏）：成员详情 `p`，进入时先显示当前值，留空保存 = 删除该参数。自动唤醒与人按 `w` 读同一份配置，行为一致。
- **陷阱**：成员若未开 `--session-control`，它**不算在岗**（见第 8 节）：不写 runtime、org 工具/技能/简报都不出现，org 消息会落 inbox 兜底；看板显示「睡眠」，按 `w` 会正常拉起一个**在岗**成员（同目录可以并存，互不覆盖——普通 pi 不再写 runtime）。

## 8. 在岗门控与在岗简报（ADR-0041 / ADR-0042 / ADR-0043 / ADR-0046）

**在岗 = 该 cwd 已注册为 org 成员 且 本进程的 control 控制 socket 真的可连**（ADR-0043 D2：socket 可连才是「能收发成员消息」的物理真相；`--session-control` flag 只表示"启动时请求建 socket"，不作判据）。进入在岗：用 `pi -a --session-control --no-permission-gate` 启动（自动上岗；第二个参数的理由见第 4 节「启动参数」），或先 `/control on` 建好 socket 再 `/org on` 显式上岗（ADR-0046 D4：运行中人工切换只到「可上岗」，是否上岗由 org 自决）。

| 面                   | 未在岗                     | 在岗                                                                     |
| -------------------- | -------------------------- | ------------------------------------------------------------------------ |
| LLM 工具（8 个 org） | 不注册（LLM 看不到）       | 全部可用                                                                 |
| org 技能             | 不贡献（系统提示里没有）   | 按角色贡献（负责人 `org-chief` / 成员 `org-member`，另附 `org-recover`） |
| 在岗简报             | 无                         | 静态块进系统提示 + 动态块追在用户轮次尾部                                |
| `/org` 命令与看板    | **照常可用**（人类操作台） | 照常可用                                                                 |

**在岗简报**（`[org 在岗简报]`）：

- **静态块**（进系统提示、会话内恒定）：我是谁（org / 角色 / 简介）+ 组织背景 + 技能指路；
- **动态块**（追在每个用户轮次尾部、随消息持久化）：在岗成员（名字 + 状态）+ 一行计数（我派 / 我接 / 待我验收 / inbox）。

**为什么分两块注入**：系统提示是 prompt cache 的断点，逐轮变化会让整条前缀缓存失效；动态块追在**新轮次尾部**（用户消息尚未被缓存）则零缓存代价。

**成员简介的刷新**：`org.json` 里的简档是快照，三处刷新——① 在岗注册时成员回写自己的；② 看板按 `r` 重读全体成员目录；③ 简报渲染时实时读（**只读不回写**，避免每轮写盘与并发丢更新）。

> 若你在成员目录里跑的 pi **没带** `--session-control`（也未在会话里执行过 `/control on` + `/org on`），它就不是该成员的在岗进程——org 工具与简报都不出现，这是设计而非故障。让它上岗：启动时 `pi -a --session-control --no-permission-gate`（`--no-permission-gate` 的理由见上文「启动参数」），先在会话里 `/control on` 再 `/org on`，或在看板里唤醒它。
